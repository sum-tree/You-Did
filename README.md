# You Did! — Motivational Productivity App

每一个小小的完成，都值得被看见。手机端优先的求职与学习效率应用：每日任务、成就、待办、日历，以及即时卡拉米奖励。

正式网站：[You Did!](https://sum-tree.github.io/You-Did/)。在iPhone Safari中打开后，可通过「分享 → 添加到主屏幕」安装。

## 在 Windows 本机启动

需要 Node.js 24 或更高版本。打开 PowerShell：

```powershell
Set-Location -LiteralPath 'E:\Github\You Did - Motivational Productivity App'
npm.cmd ci --cache .npm-cache
npm.cmd run dev
```

打开终端显示的地址，默认是 `http://127.0.0.1:5173/`。使用 `npm.cmd` 可避免 PowerShell 对 `npm.ps1` 的执行策略限制。依赖版本固定在 `package-lock.json`，换机器使用 `npm ci`，不要删除锁文件。

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run preview
```

`build` 先进行 TypeScript 检查，再生成 `dist/`；`preview` 默认使用5173以外的端口，适合检查生产构建。项目使用 Vite + React + TypeScript，无后端、账号或数据库。图标来自 lucide-react，无外部字体或图片请求。

## 如何使用

1. 在「待办」右上角「+」添加任务，填写标题，选择类型、优先级和可选截止日期。目标贡献与数量从标题识别，例如「投递3份简历」计入简历3份、「准备汇丰面试」计入面试、「粤语听力20分钟」计入听力20分钟；表单会显示识别结果。新任务计划在本周。
2. 「每日」默认自动选择2项，到期任务优先，最多3项未完成。手动安排后以所选任务为准；所有到期/逾期事项仍会在独立提醒区显示。当天完成的任务保持勾选，留在同一列表。
3. 完成任务获得5卡拉米，目标贡献计入实际完成的那一周。「成就」展示本周三类进度和奖励明细；目标与挑战规则在设置中说明。
4. 在「日历」右上角「+」单独添加重要日期与提醒，点日期查看、编辑或移除；日历事项不会自动生成任务、进度或积分。
5. 没做完的任务可以移到下周或清空。清空是可恢复的归档，不扣积分；已完成任务不能再次领取奖励。

课程初始为第6/15周，可在设置中手动调整。每个粤语贡献单位代表一整次30分钟练习。目标以周一至周日计算。

## iPhone 添加到主屏幕

应用名称为 **You Did!**，主屏幕图标已采用用户选择的C「奖励星星」。网站部署完成后，用iPhone Safari打开正式HTTPS网址，选择「分享 → 添加到主屏幕」，若出现「作为网页App打开」则开启，再点「添加」。之后从桌面图标进入。

应用清单设为`standalone`，配置了180px Apple触控图标及192px、512px应用图标，资源地址相对部署子路径。添加主屏幕不代表支持离线；本版仍需联网加载页面，尚未加入Service Worker离线缓存。未在真实iPhone上验收，部署后须检查图标、启动和刘海/底部安全区。

三个原始候选与完整生成提示词保存在`docs/icon-options/`，使用内置image_gen生成。A为完成打勾、B为成长幼苗、C为奖励星星，用户已确认C。图标没有预先裁成圆角，交由iOS应用系统遮罩。

## 数据与跨设备迁移

数据保存在浏览器 `localStorage`，初始任务和积分为空。应用不是云同步服务：不同浏览器、域名、主机名或端口的记录分别保存。例如 `localhost:5173`、`127.0.0.1:5173` 和正式部署网址属于不同存储空间。

换设备或部署网址之前，在右上角「设置与数据备份」导出 JSON；在新环境导入。导入会先验证格式，再要求确认替换现有记录，建议先导出当前备份。请勿把个人任务备份提交到公开仓库。清理浏览器数据也会清除应用记录；定期导出备份。

损坏或不兼容的存储不会被初始化逻辑自动覆盖；应用会显示错误，并允许导出原始记录。保存失败时，本次尝试可通过「导出待保存备份」另存为JSON；它仅保留在当前页面，刷新或关闭前请先导出。

多个标签页可以查看和编辑。若另一页在你打开编辑窗口后更新了记录，本次保存会停止，并保留输入及待保存备份；请先导出，再关闭并重新打开编辑窗口，核对最新记录后重做改动。任务、日历、每日安排、批量操作和备份导入都遵守这项保护。待保存备份包含本次尝试时的完整记录，导入它会替换当前记录，不会自动合并；通常应在最新记录上手动补回未保存的内容。

发布此更新后，请刷新所有已打开的旧页面，再继续编辑；旧版本页面不具备新的冲突保护。如果浏览器或网址无法提供安全写入能力，应用会暂停保存并允许导出待保存备份；正式HTTPS网址适用于本功能。真实iPhone仍需实机验收。

## 静态部署

运行 `npm.cmd run build` 后，把 `dist/` 目录部署到支持静态文件的服务即可。推荐配置：构建命令 `npm run build`、输出目录 `dist`、Node.js版本24。

- GitHub Pages：使用仓库提供的 `.github/workflows/deploy.yml`。在仓库 **Settings → Pages → Source** 选择 **GitHub Actions**，然后从 Actions 手动运行 **Deploy GitHub Pages**。该流程只由手动操作触发，不会因push自动部署。
- 其他静态托管：上传 `dist` 或设置上述构建命令与输出目录。

Vite 配置使用相对资源路径，兼容 GitHub Pages 的仓库子路径。四个页面在应用内切换，没有需要服务器重写的深层路由。部署到手机可访问的网址后直接在手机浏览器使用；本地开发服务默认只监听本机，不向局域网公开。

## GitHub 仓库

源码、锁文件、产品文档和工作流均可提交。`node_modules/`、`dist/`、npm缓存和运行日志被忽略。项目当前分支为 Git 默认初始化的 `master`，无需为继续开发切换分支。远程仓库为 [sum-tree/You-Did](https://github.com/sum-tree/You-Did)，后续push须由用户明确授权。

如果 E: 盘出现 `dubious ownership`，可仅对这次命令加精确目录参数：

```powershell
git -c safe.directory="E:/Github/You Did - Motivational Productivity App" status
```

## 已知边界

- 提醒只在应用内呈现，尚不支持后台推送、系统通知或云同步。
- 每周目标奖励自动发放，进度降低不会收回已发奖励。同一任务、同一周目标与同一挑战档位只奖励一次。
- 完成记录不可撤销，以避免重复领取；清空未完成任务可从「已清空」恢复。
- 学期周数手动维护，不假定开学日期。课程周数进度和任务完成数量是两个独立指标。
- 未采用 Habitica / Super Productivity 的源码或素材；只参考其任务与正向反馈的设计思路。
