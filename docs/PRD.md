## 1. 应用核心

**You Did! 是通过及时奖励，鼓励用户完成每天秋招和学习任务的个人效率应用。** 主要服务同时准备香港求职、口语面试及课程作业的用户，帮助用户决定今天做什么、记录已经做了什么，并看到持续积累的进步。

核心使用流程：在待办记录任务 → 每日自动安排少量任务 → 勾选完成 → 即时获得卡拉米 → 在成就查看进度；重要面试、DDL和提醒单独记入日历。

产品取舍：少量核心任务、清晰清单、及时正向反馈；保留用户手动调整节奏的能力。未完成任务允许重新安排，不扣已获积分。页面优先呈现可操作的信息，减少重复统计、装饰性口号和空状态大卡片。

## 2. 板块与整体使用方式

应用共有**4个主板块**，底部导航从左至右固定为：**成就 → 每日 → 待办 → 日历**。

| 板块 | 回答的问题 | 核心功能 | 主要操作 |
| --- | --- | --- | --- |
| 成就 | 我积累了多少进步？ | 简洁余额、本周三类进度、课程周数、奖励记录 | 查看进度与明细、调整课程周数 |
| 每日 | 今天先完成哪几件事？ | 自动/手动安排、完成勾选、同列表保留今日完成项、DDL提醒 | 完成任务、调整今日安排、手动修改DDL |
| 待办 | 我要做什么，如何安排？ | 结构化任务清单、字段查看与编辑、完成、归档恢复、跨周安排 | 右上角添加待办、操作任务行 |
| 日历 | 哪些重要日期需要记住？ | 月历、日期标记、独立重要事项与提醒 | 右上角添加提醒、点日期查看或编辑事项 |

默认首页继续为**每日**。交接文档修改了导航顺序，没有要求修改默认首页；成就排在第一个入口不代表启动时进入成就。

全局保留品牌You Did!、卡拉米余额和设置入口。设置用于课程周数、备份导出/导入、恢复与奖励规则说明，属于辅助入口，不新增第五个底部板块。待办和日历页的右上角“+”分别承担添加待办、添加提醒的主要操作，设置保留为次级入口。

以手机宽390px为参考，320px也应可用；电脑浏览器居中显示最大390px手机视图。任务清单在窄屏采用紧凑行和字段展开，主要内容无水平溢出。底部导航不遮挡最后一项，兼容顶部/底部安全区；编辑表单使用弹窗或底部面板。

正式网站可直接使用，无需电脑运行本地服务。应用名称为You Did!，主屏幕图标沿用已选C「奖励星星」；支持iOS添加到主屏幕。安装后的真实iPhone使用与备份流程仍需实机验收。

## 3. 任务类型与目标

| 类型 | 基础目标 | 特别挑战 |
| --- | --- | --- |
| 香港揾工 | 每周15份简历投递，并完成本周所有计划中的测试/面试 | 每额外3份简历一档 |
| 大胆说口语 | 每周粤语30分钟 × 2次，并完成英语面试题 × 9题 | 本周粤语或英语听力每10分钟一档 |
| 课程作业 | 学期13周课程 + 2周考试，初始第6/15周 | 本版不设特别挑战 |

任务关联目标贡献类型与数量。「投递3份简历」完成后增加3份，而不是1份。每个粤语贡献单位表示完整的一次30分钟练习；英语按题数、听力按分钟累计。测试/面试、课程和不计目标量的普通任务每项数量为1。

普通任务可不关联目标，仍归属于三种任务类型之一。课程学期进度由用户手动调整，不因完成作业自动推进周数。成就页隐藏详细计数和挑战说明，只改变呈现；本节目标仍用于实际统计和奖励。

## 4. 卡拉米奖励

| 事件 | 奖励 |
| --- | ---: |
| 完成一项普通任务（包括求职、口语任务） | 5 |
| 完成一项课程任务 | 5，属于任务奖励，不叠加第二份5 |
| 香港揾工每周基础目标达标 | 20 |
| 超出15份后，每额外投递3份简历 | 10 |
| 大胆说口语每周基础目标达标 | 20 |
| 听力每10分钟 | 5 |

完成一项任务即时显示鼓励与本次获得的卡拉米。任务奖励按任务计，目标贡献按完成数量计；一项任务投递18份简历仍只有一份任务奖励。基础目标和挑战整档自动结算，没有手动领奖步骤。

同一任务只能奖励一次，同一类型每周基础目标只能奖励一次，同一特别挑战每周每档只能奖励一次。奖励流水保留，已发奖励不因新增面试、清空或迁移任务而回退。

例：无测试/面试安排时，完成一项投递18份简历的任务，可获得5 + 20 + 10 = 35卡拉米。有未完成面试时，先只获得任务奖励5；面试完成并达标后再结算基础与超额奖励。未满一档不发分，剩余量不跨周累计。

### 5.2 每日

页面用于执行当天任务，不提供创建任务功能。新增任务统一在待办完成；本页仍可修改已有任务DDL、手动安排及移出今日。

| 模块 | 最新要求 |
| --- | --- |
| 当天信息 | 显示当前本地日期，清楚表明任务所属日 |
| 当日积累 | 保留当天完成数与当天获得卡拉米的统计，以紧凑信息呈现 |
| 今日任务列表 | 自动展示当天核心任务；未完成项为未勾选，已完成项为已勾选；完成与否均留在同一列表，每个任务ID只展示一次 |
| 完成反馈 | 勾选后成功保存才显示完成与奖励；完成项不可取消完成或再次领分 |
| 手动安排 | 保留最多3项未完成核心任务的选择、移出及恢复自动安排能力，入口保持紧凑 |
| 到期/逾期提醒 | 所有到期或逾期任务可查看，数量多时提示用户手动修改DDL；超出核心任务上限也不能漏掉 |
| 无任务状态 | 使用简短文字，例如「今天暂无任务」，保留底部待办入口，不显示添加按钮或大插画卡 |

每日列表由当天未完成核心任务和当天实际完成记录对应的任务合并组成；已完成项可使总行数超过3，但未完成核心任务仍不超过3。新文档配图关于勾选的文字存在重复“已完成”的笔误，按其「完成的勾选、完成与否都显示」的要求统一为未完成不勾选、完成勾选。

### 5.3 待办

打开页面直接展示结构化任务清单，采用类似Notion数据库表格的字段组织方式。右上角“+”添加待办；行查看与编辑继续使用现有任务操作。

| 模块 | 最新要求 |
| --- | --- |
| 添加待办 | 右上角“+”打开任务表单：必填标题，选择类型、优先级（P0/P1/P2）、可选DDL，可勾选加入今日；目标贡献与数量由标题识别（如“简历”计入简历、“面试/测试”计入面试，“投递3份简历”记3份），新任务默认本周 |
| 任务清单 | 主行优先显示完成勾选、标题、类型、DDL、优先级；计划周、目标贡献与数量可在行展开或详情中查看 |
| 任务操作 | 支持编辑/修改DDL、完成、加入或移出今日、移到下周、归档和恢复；已完成任务保留记录且不可重复计分 |
| 筛选与查看 | 保留查看本周、下周、往周、已清空及类型筛选、已完成记录的能力；收纳到清单内部的紧凑筛选入口，移除原独立分段栏和类型胶囊行 |
| 批量操作 | 从清单内部访问移至下周和清空；确认时显示受影响数量，只处理当前筛选中的未完成任务 |

页面以月历为主体，右上角“+”添加提醒。这里的提醒包括独立的测试/面试、重要DDL和其他提醒。

| 模块 | 最新要求 |
| --- | --- |
| 月历 | 显示月份、周一至周日网格，支持前后月切换、回到今天；区分今天、选中日期和非本月日期 |
| 事件标记 | 有重要事项的日期显示标记；普通待办任务不自动进入日历 |

## 6. 核心流程与交互规则（重写）

### 6.1 从记录到完成

1. 在待办右上角添加任务；输入校验通过且成功保存后，任务进入清单。
2. 每日自动安排：优先选择全部未完成的到期/逾期任务，DDL从早到晚排序，最多3项；不足2项时从本周任务按P0、P1、P2，再按DDL补到2项。
3. 手动安排优先于自动安排，严格显示所选的0至3项未完成核心任务。显式保存空选择不触发自动补齐，用户可恢复自动安排。
4. 勾选完成，贡献与奖励计入实际完成周；当天完成项保留在每日同一列表，并更新成就。
5. 过期编辑或保存失败时不显示完成/保存成功，不发放未成功保存的奖励；保留输入及可导出的本次尝试。

未来计划周的任务不参与普通自动补位；一旦到期或逾期，仍必须进入提醒与自动安排候选。往周未完成任务可以手动加入今日。自动安排可随未完成集合变化而补位；手动安排不会自动增加任务。

### 6.2 DDL、清空与跨周

到期或逾期较多时提示用户手动调整DDL，不自动把所有逾期任务推迟。未完成任务不会跨周自动删除，往周记录继续可见。

移至下周将计划周改为下一周一；早于该日期的DDL同步调整至下周一，未来DDL保留，无DDL仍可保持为空。清空是可恢复归档，完成记录和奖励流水保留。清空未完成面试不算完成，仍属于原计划周目标要求；移至下周则变为下周安排。

### 6.3 成就与日历

成就只展示简洁进度；用户可在设置查看奖励规则、调整课程周数，并通过折叠明细查看已获奖励。新增面试可能使当前进度下降，历史奖励保持不变。

日历通过右上角添加和点击日期维护事项。移除日历事件不删除待办任务，也不改变卡拉米；任务DDL修改不自动修改独立日历事件。

### 6.4 保存、反馈与手机交互

完成按钮、右上角添加、日期和关闭按钮均有清晰可访问名称；进度条可读数值，尊重系统减少动画偏好。导航与表单兼顾手机安全区，列表内容可完整滚动。

多页面同步只刷新读取结果，不反复保存。编辑窗口以打开时的记录为基准；若另一页期间已修改记录，本次改动停止保存并提示冲突，输入保留。用户可导出待保存备份，再重新打开窗口核对最新记录；不自动合并或覆盖。备份导入同样受冲突保护。具体数据要求见第9节。

| A12 | iOS主屏幕与迁移 | 实机验证图标/名称、独立窗口、任务保存及JSON导出/导入；切换入口或设备前先备份，不假定自动同步 |

第7节定义验收目标；当前实现及验证状态见第10节和[开发交接记录](STATUS.md)。

## 8. 进度与跨周规则（沿用已确认规则）

1. 双条件各计算完成比例，上限为100%，再取平均；只有两项同时达标才展示100%。无面试安排时，该条件算满足。因此未投递、无面试的一周，求职合并进度为50%。简化后的成就卡不再展示该子条件详情，设置规则应能解释其含义。
2. 临时新增测试/面试会重算本周进度，进度可降低。已发奖励不回退，同一周基础目标再次达标不重复发放；当前进度与历史已获奖励分别计算。
3. 特别挑战整周累计。基础目标达成后自动补领已完成的整档超额投递/听力奖励；未满一档的剩余量不发分，也不跨周累计。
4. 跨周任务贡献与完成奖励均计入实际完成周；清空或迁移不扣已获积分。上周计划、这周完成的面试计入这周面试目标集合；提前在更早的周完成的面试，同时满足原计划周的面试要求。移至下周导致本周目标达标时立即结算。

每周按浏览器本地日历从周一开始、到周日结束。写操作使用点击时的本地日期；跨午夜和重新聚焦/恢复可见时更新日期，避免记入旧的一天或一周。

## 9. 数据保存、备份与恢复

单用户浏览器本地持久化；刷新后恢复任务、完成记录、奖励流水、日历、每日选择和课程周数。初始任务、完成记录和余额为空/零，课程初始第6/15周。

记录属于当前设备、浏览器及访问网址，不自动跨设备或入口同步。固定使用一个入口，换设备、换网址、清理浏览器或刷新有待保存改动的页面前先导出备份。JSON导入会替换全部记录；先验证格式及任务、完成记录、每日引用、奖励之间的一致性，再确认替换。重复奖励标识、不一致的完成快照和孤立奖励须拒绝导入。

损坏或不兼容记录不被初始化覆盖，提供原始记录导出和有效备份恢复。保存失败或多页冲突可导出本次尝试的待保存JSON；它仅保留在当前页面，关闭/刷新前应导出。该文件是完整备份，导入仍会替换当前记录，不能当作自动合并补丁。

所有写操作及备份导入使用相同安全写入流程。浏览器不支持该能力时暂停保存，不降级到可能互相覆盖的写入方式。发布更新后刷新所有旧版本页面再继续编辑，使所有页面遵守同一保护流程。
