## 1. 产品目标

通过及时奖励和正向鼓励，帮助用户完成每天的秋招投递、口语练习与课程学习任务。以清晰的任务管理、可见的目标进度和轻度游戏化奖励为核心，不引入账号、排行榜、付费或复杂养成系统。

## 2. 设备与交互

React + TypeScript Web App，手机端优先。390 × 844为参考画布；窄屏自适应，电脑端保持居中的最大390px手机布局。底部四个入口为每日、成就、待办、日历，每日为默认首页。顶部显示品牌、卡拉米余额和设置入口。内容纵向滚动，导航不遮挡最后一项；表单使用底部弹窗。

## 3. 类型与目标

| 类型 | 基础目标 | 特别挑战 |
| --- | --- | --- |
| 香港揾工 | 每周15份简历投递，并完成本周所有计划中的测试/面试 | 每额外3份简历一档 |
| 大胆说口语 | 每周粤语30分钟 × 2次，并完成英语面试题 × 9题 | 本周粤语或英语听力每10分钟一档 |
| 课程作业 | 学期13周课程 + 2周考试，初始第6/15周 | 本版不设特别挑战 |

任务关联目标贡献类型与数量。「投递3份简历」完成后增加3份，而不是1份。每个粤语贡献单位必须表示完整的一次30分钟练习；测试/面试任务每项表示一项安排。普通任务可不关联目标。课程学期进度可手动调整，不因完成作业自动推进周数。

## 4. 卡拉米奖励

| 事件 | 奖励 |
| --- | ---: |
| 完成普通任务 | 5 |
| 完成课程任务 | 5，属于普通任务奖励，不叠加 |
| 香港揾工每周基础目标 | 20 |
| 额外投递每3份简历 | 10 |
| 大胆说口语每周基础目标 | 20 |
| 听力每10分钟 | 5 |

完成任务即时提示奖励与鼓励语。基础目标和挑战档位自动结算；没有手动领奖步骤。使用唯一奖励标识防止重复发放：任务完成一次、每类基础目标每周一次、每类特别挑战每周每档一次。

例：无测试/面试安排时，完成一项投递18份简历的任务，可获得5 + 20 + 10 = 35卡拉米。有未完成面试时，先只获得普通任务5；面试完成后再结算基础与超额奖励。

## 5. 每日任务

- 最多3项核心任务；完成记录可单独展示，不计入当前未完成核心任务上限。
- 用户未手动安排时，优先选择全部未完成的到期/逾期任务，按截止日期从早到晚排序，最多选3项。到期任务不足2项时，从本周任务池按P0、P1、P2和截止日期补到2项。
- 超出上限的到期任务不隐藏：独立提醒区展示所有到期/逾期任务，提供修改DDL入口。任务重复出现于提醒区属于提醒，不复制任务记录。
- 用户手动安排后，核心区严格显示其所选的0至3项。明确清空今日安排不触发自动补齐，用户可恢复自动安排；所有紧急任务仍在提醒区可见。
- 手动添加、移出或更换核心任务不改变原任务的完成状态。
- 即使计划周被设置为未来，到期/逾期任务仍须出现在提醒和自动安排候选中。

## 6. 待办任务

支持任务创建、编辑、完成、清空、恢复、加入今日、移到下周。必填标题，类型为三类之一，优先级为P0/P1/P2，可不设截止日期；记录计划周、目标贡献和数量。

本周/下周/往周/已清空分别查看，并可按类型筛选及显示已完成。未完成任务不会在跨周时自动删除；往周记录继续可见，逾期记录进入提醒区。移至下周时计划周改为下一周一；早于该日期的DDL同步调整至下周一，未来DDL保留，用户可继续手动修改。批量操作仅影响当前筛选中的未完成任务。

清空是归档而非永久删除，可恢复。已完成任务及奖励流水保留，不允许通过清空或再次点击完成来重复发分。清空未完成面试不视作完成，仍属于原计划周的目标要求；移至下周则变为下周安排。

## 7. 日历

月历支持切换月份、回到今天、选中日期及事件标记。事件有标题、日期、可选时间、类型和备注，类型为测试/面试、重要DDL、提醒。

日历只显示独立创建的重要日期与提醒，不显示普通待办任务。日历事件与任务独立，添加面试事件不自动建立面试任务或发放奖励；需要计入基础目标时另建面试任务。提醒目前只在打开应用时查看，不承诺系统通知。

## 8. 进度与跨周规则（本轮已确认）

1. 双条件各计算完成比例，上限为100%，再取平均；只有两项同时达标才展示100%。无面试安排时，该条件算满足。因此未投递、无面试的一周，求职合并进度为50%，同时显示0/15份与「暂无安排·已满足」，避免误解。
2. 临时新增测试/面试会重算本周进度，进度可降低。已发的奖励不回退，同一周基础目标再次达标不重复发放。
3. 特别挑战整周累计。基础目标达成后，自动补领已经完成的整档超额投递/听力奖励；未满一档的剩余量不发分，也不跨周累计。
4. 跨周任务贡献与完成奖励均计入实际完成周；清空或迁移不扣已获积分。上周计划、这周完成的面试计入这周的面试目标集合。

每周从本地时间周一开始，到周日结束。日期按浏览器本地日历计算；页面跨午夜或重新聚焦时刷新当前日期。

## 9. 保存与恢复

单用户浏览器本地持久化，刷新后恢复任务、完成记录、奖励流水、日历、每日选择和课程周数。空初始任务/余额，不预填虚假的完成记录。提供JSON导出/导入支持本机与设备之间迁移；导入先校验，再提示替换确认。损坏记录不会被自动覆盖，保存失败必须可见。

## 10. 验收

- 手机宽390px、320px均无水平溢出；电脑居中390px；底部四页切换和滚动正常。
- 任务CRUD、手动安排、优先级自动安排和独立DDL提醒均可操作，核心区不超过3项。
- 任务完成只奖励5；课程不重复计分；刷新、重复结算不重复发奖。
- 双条件达标、临时增加面试、特别挑战补领与整档计算符合第8节。
- 清空/跨周不扣积分；实际完成周正确统计；下周任务不会因普通自动填充提前出现。
- 日历重要事项可新增、编辑、移除，普通待办不自动出现在日历。
- 数据刷新恢复，JSON备份有效，无效导入不替换现有记录。
- README包含本地启动、验证、静态部署、迁移与已知边界；仓库忽略依赖、构建输出与缓存。
